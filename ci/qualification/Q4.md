# Q4 — M2 batch 1: DF, DU, Find

Status: **READY FOR LOCAL QUALIFICATION**

Q4 begins the M2 DOS/filesystem milestone on the same hard real-classic gate used by Q1–Q3:

- A500-class / Motorola 68000 / OCS PAL
- 512 KiB Chip RAM, no Fast/Slow RAM
- genuine Kickstart 1.2
- matching Workbench/AmigaDOS 1.2
- no FPU, no JIT, real CPU speed
- visible FS-UAE session
- exact host-built binaries copied to a private writable copy of the verified Workbench disk
- AROS remains supporting smoke/regression evidence only

Q4 also introduces `src/common/start_cli_args.S` and `src/common/start_cli_args.c`: a minimal 1.2-compatible CLI startup that receives the classic AmigaDOS D0/A0 command line and constructs `argc/argv` without `ReadArgs()`, `utility.library`, libnix automatic startup, or a C library dependency. This is required because `DU` and `Find` take command-line arguments; the Q1–Q3 startup is intentionally argument-free.

## Build gate

Run:

```sh
bash ci/qualification/build-q4.sh
```

The gate builds `DF`, `DU`, and `Find` for 68000 with the argument-aware minimal startup, rejects unresolved/automatic runtime initialization, and rejects accidental `utility.library`/`ixemul.library` dependencies.

## Controlled guest fixture

The local harness creates a private copy of the verified Workbench disk and adds:

```text
SYS:Q4/Test/Alpha.txt
SYS:Q4/Test/NeedleFile.txt
SYS:Q4/Test/Sub/Nested.txt
```

The original Workbench image is never modified. The fixture gives `DU` and `Find` deterministic classic-DOS content to traverse while `DF` observes the mounted volume normally.

## Q4.1 — DF

Invocation:

```text
DF
```

PASS requires:

- starts and exits normally with RC 0;
- identifies `DF 0.1`;
- prints `BlockSize Total Used Free Name`;
- safely traverses the AmigaOS 1.2 DOS `DevInfo` list;
- reports at least one mounted volume in the booted environment;
- numeric rows satisfy `Used <= Total` and `Free = Total - Used`;
- unavailable `Info()` data may be shown with `?` without crashing;
- no Guru, hang, traversal loop or corrupt BSTR/name output.

This is specifically evidence for the implementation's classic `RootNode`/`DosInfo`/`DevInfo` assumptions and `Info()` behavior on real 1.2 DOS.

## Q4.2 — DU

Invocation:

```text
DU SYS:Q4/Test
```

PASS requires:

- argument-aware startup passes the path correctly;
- starts and exits normally with RC 0;
- identifies `DU 0.1`;
- prints `Bytes Files Dirs Errors Path`;
- recursively traverses the controlled directory using `Lock`, `Examine`, and `ExNext`;
- observes at least the two top-level files plus the nested file and both directory levels;
- reports a positive byte count and `Errors 0`;
- path is reported as `SYS:Q4/Test`;
- no stack corruption, Guru, hang, recursion error or malformed FileInfoBlock data.

This test also validates the static/aligned `FileInfoBlock` storage and classic `ERROR_NO_MORE_ENTRIES` handling used by the implementation.

## Q4.3 — Find

Invocation:

```text
Find Needle SYS:Q4/Test
```

PASS requires:

- argument-aware startup passes both pattern and path correctly;
- starts and exits normally with RC 0;
- identifies `Find 0.1`;
- finds `SYS:Q4/Test/NeedleFile.txt` case-insensitively;
- reports at least one match and `Errors: 0`;
- recursively traverses the fixture without Guru, hang, recursion error or corrupt names.
